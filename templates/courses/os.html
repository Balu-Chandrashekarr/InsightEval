Processes

What is a Process?

A process is a program in execution, encompassing its code, data, stack, heap, and state (e.g., program counter, registers). It’s the fundamental unit of execution in an OS, running in its own isolated memory space to prevent interference. Each process has a Process Control Block (PCB) that stores metadata like process ID, state, and resource usage.

  • Components: Code (text segment), data (global variables), stack (function calls), heap (dynamic memory).
  • States: New (created), Ready (awaiting CPU), Running (executing), Waiting (I/O or event), Terminated (completed).
  • Attributes: Process ID (PID), priority, memory limits, open files.

Process Creation in C++

Processes are created using system calls like fork() on Unix or CreateProcess on Windows. The fork() system call creates a child process that’s a copy of the parent.

Example (Unix fork):

#include 
#include 

int main() {
    pid_t pid = fork(); // Create child process
    if (pid == 0) {
        printf("Child process, PID: %d, Parent PID: %d\n", getpid(), getppid());
    } else if (pid > 0) {
        printf("Parent process, PID: %d, Child PID: %d\n", getpid(), pid);
        sleep(1); // Ensure child prints first
    } else {
        printf("Fork failed\n");
    }
    return 0;
}

Example (Executing a Program):

#include 
#include 

int main() {
    pid_t pid = fork();
    if (pid == 0) {
        execl("/bin/ls", "ls", "-l", NULL); // Replace child with ls command
        printf("execl failed\n");
    } else if (pid > 0) {
        wait(NULL); // Wait for child to finish
        printf("Parent process done\n");
    } else {
        printf("Fork failed\n");
    }
    return 0;
}

Process Scheduling

The OS schedules processes to share CPU time, using algorithms like First-Come-First-Serve (FCFS), Round-Robin (RR), or Priority Scheduling. Scheduling ensures fair resource allocation and responsiveness.

  • FCFS: Executes processes in arrival order; simple but may cause delays.
  • Round-Robin: Allocates fixed time slices (quantum) for fairness.
  • Priority Scheduling: Prioritizes high-priority processes, risking starvation for low-priority ones.

Uses of Processes

  • Multitasking: Run multiple applications (e.g., browser, editor) simultaneously.
  • Isolation: Separate memory spaces prevent crashes from affecting other processes.
  • System Services: Manage daemons (background processes) like logging or networking.
  • Parallel Processing: Divide tasks across processes for distributed systems.
  • Inter-Process Communication (IPC): Enable processes to share data via pipes, message queues, or shared memory.

Additional Notes

  • Process Control Block (PCB): Critical for context switching; stores CPU registers, memory maps, and I/O status.
  • Context Switching: Overhead from saving/restoring process state; minimized in efficient OS designs.
  • Zombie/Orphan Processes: Zombies are terminated but not reaped; orphans are adopted by the init process.
  • Limitations: Processes are heavyweight due to separate memory; threads are lighter alternatives.
  • Real-World Example: Processes run your IDE, web server, or database, isolating tasks for stability.

Threads

What is a Thread?

A thread is the smallest unit of execution within a process, sharing the process’s memory and resources. Threads enable parallelism, allowing multiple tasks to run concurrently within a single process, improving performance on multi-core systems.

  • Types: User threads (application-managed) and kernel threads (OS-managed).
  • Shared Resources: Threads share code, data, and files but maintain separate stacks and registers.
  • Thread States: New, Runnable, Blocked, Waiting, Timed Waiting, Terminated.

Creating Threads in Java

Java supports threading via the Thread class or Runnable interface. The ExecutorService is preferred for managing thread pools.

Example (Using Runnable):

public class MyThread implements Runnable {
    public void run() {
        for (int i = 1; i <= 3; i++) {
            System.out.println(Thread.currentThread().getName() + ": Count " + i);
            try {
                Thread.sleep(100); // Simulate work
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }
    }
    public static void main(String[] args) {
        Thread t1 = new Thread(new MyThread(), "Thread-1");
        Thread t2 = new Thread(new MyThread(), "Thread-2");
        t1.start();
        t2.start();
    }
}

Example (Using ExecutorService):

import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class ThreadPoolExample {
    public static void main(String[] args) {
        ExecutorService executor = Executors.newFixedThreadPool(2);
        for (int i = 1; i <= 4; i++) {
            final int taskId = i;
            executor.submit(() -> {
                System.out.println("Task " + taskId + " running on " + Thread.currentThread().getName());
            });
        }
        executor.shutdown();
    }
}

Thread Lifecycle and Management

Threads transition through states, and Java provides methods to control them:

  • start(): Begins thread execution; calls run().
  • sleep(millis): Pauses thread for specified time.
  • join(): Waits for a thread to complete.
  • interrupt(): Signals a thread to stop (handled by application).

Uses of Threads

  • Parallel Execution: Run computations and I/O tasks simultaneously.
  • Performance: Leverage multi-core CPUs for faster execution.
  • Responsiveness: Keep GUIs responsive during background tasks.
  • Server Applications: Handle multiple client requests concurrently.
  • Event Handling: Process asynchronous events in real-time systems.

Additional Notes

  • Thread Safety: Shared resources require synchronization to prevent data corruption.
  • Thread Pools: ExecutorService reduces overhead of creating/destroying threads.
  • Thread Priorities: Java allows setting priorities, but scheduling depends on the OS.
  • Limitations: Threads share memory, risking race conditions; use synchronization carefully.
  • Real-World Example: Threads power web servers (handling HTTP requests), game engines (rendering and physics), and database query processing.

Memory Management

What is Memory Management?

Memory management is the process of allocating, tracking, and deallocating memory for processes and threads. The OS ensures efficient use of RAM, prevents memory leaks, and isolates process memory spaces to avoid interference.

  • Types: Paging (fixed-size blocks), Segmentation (variable-size segments), Virtual Memory (disk-backed memory).
  • Goals: Minimize fragmentation, ensure process isolation, optimize allocation speed.
  • Virtual Memory: Maps virtual addresses to physical memory, enabling large address spaces.

Memory Allocation in C++

In C++, memory is allocated dynamically on the heap using new and deallocated with delete. Stack allocation is automatic for local variables.

Example (Dynamic Allocation):

#include 
int main() {
    int* arr = new int[5]; // Allocate array on heap
    for (int i = 0; i < 5; i++) {
        arr[i] = i + 1;
        std::cout << arr[i] << " "; // Prints: 1 2 3 4 5
    }
    delete[] arr; // Deallocate array
    return 0;
}

Example (Smart Pointers):

#include 
#include 
int main() {
    std::unique_ptr ptr = std::make_unique(42); // Smart pointer
    std::cout << "Value: " << *ptr << std::endl; // Prints: 42
    // Automatically deallocated when out of scope
    return 0;
}

Virtual Memory and Paging

Virtual memory allows processes to use more memory than physically available by swapping data to disk. Paging divides memory into fixed-size pages, mapped via page tables.

  • Page Table: Maps virtual addresses to physical memory.
  • Page Fault: Occurs when a page is not in RAM; OS loads it from disk.
  • TLB: Translation Lookaside Buffer caches page table entries for speed.

Uses of Memory Management

  • Process Isolation: Prevent processes from accessing unauthorized memory.
  • Virtual Memory: Run large programs on limited RAM.
  • Efficiency: Optimize memory allocation for multitasking.
  • Dynamic Allocation: Support runtime memory needs (e.g., heap allocation).
  • Memory Protection: Enforce access controls via memory management units (MMU).

Additional Notes

  • Fragmentation: Internal (unused space in allocated blocks) vs. external (gaps between blocks).
  • Garbage Collection: Java’s JVM automatically reclaims unused memory, unlike C++’s manual management.
  • Page Replacement: Algorithms like LRU (Least Recently Used) manage page faults.
  • Best Practices: Avoid memory leaks in C++; use smart pointers or RAII for safety.
  • Real-World Example: Memory management enables running multiple apps on smartphones or virtual machines in cloud systems.

File Systems

What is a File System?

A file system organizes, stores, and retrieves data on storage devices like hard drives or SSDs. It manages files, directories, and metadata, providing a structured way to access data. The OS interacts with the file system to perform operations like reading, writing, and deleting files.

  • Types: FAT32 (simple, portable), NTFS (Windows, advanced features), ext4 (Linux, efficient).
  • Components: Directory structure (tree-like), file metadata (size, permissions), data blocks (actual content).
  • Features: Permissions, journaling, hierarchical organization.

File Operations in Java

Java’s java.io and java.nio.file packages provide robust file handling capabilities.

Example (File Read/Write):

import java.io.BufferedReader;
import java.io.FileReader;
import java.io.FileWriter;
import java.io.IOException;

public class FileExample {
    public static void main(String[] args) {
        // Write to file
        try (FileWriter writer = new FileWriter("example.txt")) {
            writer.write("Hello, Operating Systems!\n");
        } catch (IOException e) {
            System.out.println("Write error: " + e.getMessage());
        }
        // Read from file
        try (BufferedReader reader = new BufferedReader(new FileReader("example.txt"))) {
            String line;
            while ((line = reader.readLine()) != null) {
                System.out.println(line); // Prints: Hello, Operating Systems!
            }
        } catch (IOException e) {
            System.out.println("Read error: " + e.getMessage());
        }
    }
}

Example (File Attributes):

import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.attribute.BasicFileAttributes;
import java.io.IOException;

public class FileAttributes {
    public static void main(String[] args) {
        Path path = Path.of("example.txt");
        try {
            BasicFileAttributes attrs = Files.readAttributes(path, BasicFileAttributes.class);
            System.out.println("Size: " + attrs.size() + " bytes");
            System.out.println("Last Modified: " + attrs.lastModifiedTime());
        } catch (IOException e) {
            System.out.println("Error: " + e.getMessage());
        }
    }
}

File System Structure

File systems use a hierarchical structure, with a root directory and nested subdirectories. Metadata includes permissions, timestamps, and ownership.

  • Inodes (Unix): Store file metadata except name; used in ext4.
  • Journaling: Logs changes to prevent data loss (e.g., NTFS, ext4).
  • Allocation Methods: Contiguous, linked, or indexed allocation for data blocks.

Uses of File Systems

  • Data Persistence: Store user files, configurations, or databases.
  • Hierarchical Organization: Manage files in directories for easy navigation.
  • Access Control: Enforce permissions for security (e.g., read-only for users).
  • Data Integrity: Journaling ensures reliability during crashes.
  • Backup and Recovery: Support snapshots or versioning (e.g., ZFS).

Additional Notes

  • File System Types: Choose based on use case (e.g., FAT32 for USB drives, NTFS for Windows).
  • Performance: Use buffered I/O to reduce disk access overhead.
  • Security: Implement file permissions and encryption for sensitive data.
  • Best Practices: Always handle I/O exceptions; close resources using try-with-resources.
  • Real-World Example: File systems manage user data in cloud storage (e.g., Google Drive) or OS file explorers.

Synchronization

What is Synchronization?

Synchronization ensures orderly access to shared resources in concurrent environments, preventing race conditions and ensuring data consistency. It’s critical in multi-threaded or multi-process systems where multiple entities access shared data.

  • Mechanisms: Locks (mutexes), semaphores, monitors, condition variables.
  • Issues: Race conditions, deadlocks, starvation, priority inversion.
  • Goals: Ensure mutual exclusion, avoid data corruption, maintain system fairness.

Synchronization in Java

Java provides synchronization via the synchronized keyword, Lock interface, and concurrent utilities like ReentrantLock.

Example (Synchronized Block):

public class SharedResource {
    private int count = 0;
    public void increment() {
        synchronized (this) { // Synchronize on object
            count++;
            System.out.println(Thread.currentThread().getName() + ": " + count);
        }
    }
    public static void main(String[] args) {
        SharedResource resource = new SharedResource();
        Runnable task = () -> {
            for (int i = 0; i < 5; i++) {
                resource.increment();
                try {
                    Thread.sleep(10);
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
            }
        };
        Thread t1 = new Thread(task, "Thread-1");
        Thread t2 = new Thread(task, "Thread-2");
        t1.start();
        t2.start();
    }
}

Example (ReentrantLock):

import java.util.concurrent.locks.ReentrantLock;

public class LockExample {
    private int count = 0;
    private final ReentrantLock lock = new ReentrantLock();
    public void increment() {
        lock.lock();
        try {
            count++;
            System.out.println(Thread.currentThread().getName() + ": " + count);
        } finally {
            lock.unlock();
        }
    }
    public static void main(String[] args) {
        LockExample example = new LockExample();
        Runnable task = () -> {
            for (int i = 0; i < 5; i++) example.increment();
        };
        Thread t1 = new Thread(task, "Thread-1");
        Thread t2 = new Thread(task, "Thread-2");
        t1.start();
        t2.start();
    }
}

Synchronization Primitives

Common synchronization tools include:

  • Mutex: Ensures only one thread accesses a resource (mutual exclusion).
  • Semaphore: Controls access by multiple threads with a counter (e.g., for limited resources).
  • Condition Variables: Allow threads to wait for specific conditions (e.g., wait()/notify() in Java).
  • Monitors: Combine mutex and condition variables; Java’s synchronized implements monitors.

Uses of Synchronization

  • Data Consistency: Protect shared data like counters or buffers.
  • Thread Coordination: Ensure tasks execute in the correct order.
  • Resource Sharing: Manage access to limited resources (e.g., database connections).
  • Concurrent Systems: Enable safe multi-threading in servers or applications.
  • Producer-Consumer: Coordinate producers (adding data) and consumers (processing data).

Additional Notes

  • Deadlock Avoidance: Use resource ordering, timeouts, or deadlock detection algorithms.
  • Java Concurrent Utilities: ConcurrentHashMap, BlockingQueue for thread-safe collections.
  • Performance: Minimize synchronized code to reduce contention; prefer fine-grained locks.
  • Best Practices: Use try-finally with locks; test for race conditions in concurrent code.
  • Real-World Example: Synchronization ensures thread safety in web servers (e.g., Apache), databases (e.g., transaction locks), and OS kernels.
