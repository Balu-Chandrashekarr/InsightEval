Relational Model

What is the Relational Model?

The relational model organizes data into tables (relations), where each table consists of rows (tuples) and columns (attributes). It uses keys to establish relationships between tables, ensuring data integrity and efficient querying.

  • Table: A collection of rows with the same attributes.
  • Primary Key: Uniquely identifies each row.
  • Foreign Key: Links tables by referencing a primary key in another table.
  • Schema: Defines the structure of tables and relationships.

Example Schema

Consider a database for a library system with two tables: Books and Borrowers.

Books Table:

CREATE TABLE Books (
    book_id INT PRIMARY KEY,
    title VARCHAR(100),
    author VARCHAR(50),
    publication_year INT
);

Borrowers Table:

CREATE TABLE Borrowers (
    borrower_id INT PRIMARY KEY,
    name VARCHAR(50),
    book_id INT,
    FOREIGN KEY (book_id) REFERENCES Books(book_id)
);

Relational Algebra

Relational algebra provides a theoretical foundation for querying databases using operations like selection, projection, join, and union.

  • Selection: Filters rows based on conditions (e.g., books published after 2000).
  • Projection: Selects specific columns (e.g., book titles).
  • Join: Combines tables based on keys (e.g., Books and Borrowers).

Uses of the Relational Model

  • Data Organization: Structure data in tables for clarity and consistency.
  • Relationships: Model complex relationships using keys.
  • Querying: Enable efficient data retrieval with SQL.
  • Scalability: Support large datasets in enterprise systems.
  • Data Integrity: Enforce constraints like primary and foreign keys.

Additional Notes

  • Constraints: NOT NULL, UNIQUE, CHECK ensure data validity.
  • Normalization: Reduces redundancy, covered in a later section.
  • Best Practices: Use meaningful table/column names; enforce keys for integrity.
  • Real-World Example: Relational databases power e-commerce (product catalogs), banking (accounts), and CRM systems.
  • Alternatives: NoSQL databases (e.g., MongoDB) for unstructured data.

SQL

What is SQL?

Structured Query Language (SQL) is a standardized language for managing and querying relational databases. It supports Data Definition Language (DDL), Data Manipulation Language (DML), Data Control Language (DCL), and Transaction Control Language (TCL) operations, enabling comprehensive database management.

  • DDL: Define and modify database structures (e.g., CREATE, ALTER, DROP).
  • DML: Manipulate data (e.g., INSERT, UPDATE, DELETE, SELECT).
  • DCL: Manage access and permissions (e.g., GRANT, REVOKE).
  • TCL: Control transactions (e.g., COMMIT, ROLLBACK).

SQL Commands

SQL commands cover a wide range of operations for creating, querying, and managing databases. Below are examples using the library schema.

DDL: Create and Alter Table

-- Create table
CREATE TABLE Books (
    book_id INT PRIMARY KEY,
    title VARCHAR(100) NOT NULL,
    author VARCHAR(50),
    publication_year INT CHECK (publication_year > 1800)
);

-- Alter table to add column
ALTER TABLE Books ADD genre VARCHAR(50);

-- Drop table
DROP TABLE Books;

DML: Insert, Update, Delete, Select

-- Insert data
INSERT INTO Books (book_id, title, author, publication_year, genre)
VALUES (1, '1984', 'George Orwell', 1949, 'Dystopian');

-- Update data
UPDATE Books
SET genre = 'Science Fiction'
WHERE book_id = 1;

-- Delete data
DELETE FROM Books
WHERE publication_year < 1900;

-- Select with conditions
SELECT title, author
FROM Books
WHERE publication_year > 2000
ORDER BY title;

Advanced Queries: Joins and Aggregations

-- Inner join
SELECT b.title, br.name
FROM Books b
INNER JOIN Borrowers br ON b.book_id = br.book_id;

-- Group by and aggregate
SELECT author, COUNT(*) as book_count
FROM Books
GROUP BY author
HAVING COUNT(*) > 2
ORDER BY book_count DESC;

-- Subquery
SELECT title
FROM Books
WHERE book_id IN (SELECT book_id FROM Borrowers WHERE name = 'Alice');

DCL: Permissions

-- Grant read access
GRANT SELECT ON Books TO user_read;

-- Revoke access
REVOKE SELECT ON Books FROM user_read;

TCL: Transaction Control

-- Start transaction
START TRANSACTION;

-- Insert data
INSERT INTO Books (book_id, title, author) VALUES (2, 'Brave New World', 'Aldous Huxley');

-- Commit transaction
COMMIT;

-- Rollback example
START TRANSACTION;
INSERT INTO Books (book_id, title) VALUES (3, 'Invalid Book');
ROLLBACK;

SQL with Java (JDBC)

Java Database Connectivity (JDBC) enables Java programs to execute SQL commands for dynamic database interaction.

Example (Multiple SQL Operations):

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;

public class JdbcExample {
    public static void main(String[] args) {
        String url = "jdbc:mysql://localhost:3306/library";
        String user = "root";
        String password = "password";
        try (Connection conn = DriverManager.getConnection(url, user, password)) {
            // Insert
            String insertSql = "INSERT INTO Books (book_id, title, author, publication_year) VALUES (?, ?, ?, ?)";
            PreparedStatement insertStmt = conn.prepareStatement(insertSql);
            insertStmt.setInt(1, 4);
            insertStmt.setString(2, "The Great Gatsby");
            insertStmt.setString(3, "F. Scott Fitzgerald");
            insertStmt.setInt(4, 1925);
            insertStmt.executeUpdate();
            System.out.println("Book inserted");

            // Select with condition
            String selectSql = "SELECT title, author FROM Books WHERE publication_year > ?";
            PreparedStatement selectStmt = conn.prepareStatement(selectSql);
            selectStmt.setInt(1, 2000);
            ResultSet rs = selectStmt.executeQuery();
            while (rs.next()) {
                System.out.println(rs.getString("title") + " by " + rs.getString("author"));
            }

            // Update
            String updateSql = "UPDATE Books SET genre = ? WHERE book_id = ?";
            PreparedStatement updateStmt = conn.prepareStatement(updateSql);
            updateStmt.setString(1, "Classic");
            updateStmt.setInt(2, 4);
            updateStmt.executeUpdate();
            System.out.println("Book updated");

            // Delete
            String deleteSql = "DELETE FROM Books WHERE publication_year < ?";
            PreparedStatement deleteStmt = conn.prepareStatement(deleteSql);
            deleteStmt.setInt(1, 1900);
            deleteStmt.executeUpdate();
            System.out.println("Old books deleted");
        } catch (SQLException e) {
            System.out.println("Error: " + e.getMessage());
        }
    }
}

Query Optimization Techniques

Optimizing SQL queries improves performance, especially for large datasets.

  • Use Indexes: Create indexes on frequently queried columns.
  • Avoid SELECT *: Specify only needed columns to reduce data transfer.
  • Parameterized Queries: Prevent SQL injection and improve execution plans.
  • Analyze Query Plans: Use EXPLAIN to understand query execution.

Uses of SQL

  • Data Retrieval: Generate reports or dashboards from large datasets.
  • Data Manipulation: Update records dynamically (e.g., user profiles).
  • Schema Management: Define and modify database structures.
  • Integration: Connect applications via JDBC or ORMs (e.g., Hibernate).
  • Security: Manage user permissions for controlled access.
  • Data Analysis: Perform aggregations for business intelligence.

Additional Notes

  • Aggregate Functions: COUNT, SUM, AVG, MIN, MAX for summarizing data.
  • Subqueries and Joins: Use for complex filtering and combining data.
  • Best Practices: Use parameterized queries; avoid dynamic SQL in production.
  • Real-World Example: SQL powers e-commerce platforms, financial systems, and analytics tools.
  • Performance: Optimize queries with indexes; monitor execution time.
  • SQL Variants: MySQL, PostgreSQL, Oracle SQL have slight syntax differences.

Joins

What are Joins?

Joins combine rows from two or more tables based on a related column, typically a primary key or foreign key. They enable querying data across multiple tables, leveraging the relational model to retrieve meaningful results.

  • Inner Join: Returns rows where there is a match in both tables.
  • Left (Outer) Join: Returns all rows from the left table, with matching rows from the right table (NULL if no match).
  • Right (Outer) Join: Returns all rows from the right table, with matching rows from the left table (NULL if no match).
  • Full (Outer) Join: Returns all rows from both tables, with NULLs where there is no match.
  • Cross Join: Returns the Cartesian product of both tables (all possible combinations).

Join Examples in SQL

Using the library schema (Books and Borrowers), here are examples of different joins.

Inner Join: Books borrowed by users

SELECT b.title, br.name
FROM Books b
INNER JOIN Borrowers br ON b.book_id = br.book_id;

Left Join: All books, including those not borrowed

SELECT b.title, br.name
FROM Books b
LEFT JOIN Borrowers br ON b.book_id = br.book_id;

Right Join: All borrowers, including those without books

SELECT b.title, br.name
FROM Books b
RIGHT JOIN Borrowers br ON b.book_id = br.book_id;

Full Join: All books and borrowers, with NULLs for non-matches

SELECT b.title, br.name
FROM Books b
FULL JOIN Borrowers br ON b.book_id = br.book_id;

Cross Join: All possible book-borrower combinations

SELECT b.title, br.name
FROM Books b
CROSS JOIN Borrowers br;

Joins with Java (JDBC)

Java (JDBC) can execute join queries to retrieve related data programmatically.

Example (Inner Join with JDBC):

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;

public class JoinExample {
    public static void main(String[] args) {
        String url = "jdbc:mysql://localhost:3306/library";
        String user = "root";
        String password = "password";
        String sql = "SELECT b.title, br.name FROM Books b INNER JOIN Borrowers br ON b.book_id = br.book_id";
        try (Connection conn = DriverManager.getConnection(url, user, password);
             PreparedStatement stmt = conn.prepareStatement(sql);
             ResultSet rs = stmt.executeQuery()) {
            while (rs.next()) {
                String title = rs.getString("title");
                String name = rs.getString("name");
                System.out.println("Book: " + title + ", Borrowed by: " + name);
            }
        } catch (SQLException e) {
            System.out.println("Error: " + e.getMessage());
        }
    }
}

Join Optimization

Optimizing joins improves query performance, especially for large tables.

  • Use Indexes: Index join columns (e.g., book_id) for faster lookups.
  • Specify Join Conditions: Use precise ON clauses to avoid unnecessary comparisons.
  • Avoid Unnecessary Joins: Only join tables needed for the query.
  • Use EXPLAIN: Analyze join performance with query execution plans.

Uses of Joins

  • Data Integration: Combine related data from multiple tables (e.g., orders and customers).
  • Reporting: Generate reports by joining tables (e.g., sales and products).
  • Relational Queries: Retrieve complex relationships in a single query.
  • Data Analysis: Aggregate data across tables for insights.
  • Application Development: Fetch related data for application logic.

Additional Notes

  • Join Types Trade-offs: Inner joins are faster but exclude non-matching rows; outer joins are inclusive but slower.
  • Self-Join: Join a table with itself for hierarchical data (e.g., employee-manager relationships).
  • Best Practices: Use aliases for readability; index join columns; test query performance.
  • Real-World Example: Joins power e-commerce (products and orders), social media (users and posts), and HR systems (employees and departments).
  • Performance: Avoid excessive joins in high-traffic systems; consider denormalization for read-heavy workloads.

Normalization

What is Normalization?

Normalization is the process of organizing a database to eliminate redundancy and ensure data integrity by dividing tables into smaller, related tables based on functional dependencies. It follows normal forms (1NF, 2NF, 3NF, BCNF).

  • 1NF: Ensure atomic values and no repeating groups.
  • 2NF: Remove partial dependencies; non-key attributes depend on the entire primary key.
  • 3NF: Eliminate transitive dependencies.

Normalization Example

Consider an unnormalized table for student courses.

Unnormalized Table:

Student (student_id, name, course1, course2)

1NF (Atomic Values):

StudentCourses (student_id, name, course)

2NF (Split Partial Dependencies):

Students (student_id, name)
StudentCourses (student_id, course)

3NF (Remove Transitive Dependencies):

Students (student_id, name)
Courses (course_id, course_name)
StudentCourses (student_id, course_id)

Normalization Process

Steps to normalize a database:

  • Identify Functional Dependencies: Determine how attributes depend on each other.
  • Apply Normal Forms: Progress through 1NF, 2NF, 3NF, and optionally BCNF.
  • Test Integrity: Ensure no data anomalies (insert, update, delete).

Uses of Normalization

  • Reduce Redundancy: Minimize duplicate data to save storage.
  • Data Integrity: Prevent anomalies during updates or deletes.
  • Efficient Queries: Simplify joins and data retrieval.
  • Scalability: Support large databases with complex relationships.
  • Maintainability: Easier to modify schema without data loss.

Additional Notes

  • Denormalization: Intentionally add redundancy for performance in read-heavy systems.
  • BCNF: Advanced form for complex schemas; rarely needed.
  • Best Practices: Normalize to 3NF for most applications; balance with performance needs.
  • Real-World Example: Normalized databases are used in banking (account management) and retail (inventory systems).
  • Tools: Use ER diagrams to visualize relationships before normalizing.

Transactions

What are Transactions?

A transaction is a sequence of database operations that executes as a single unit, ensuring data consistency. Transactions follow the ACID properties: Atomicity, Consistency, Isolation, Durability.

  • Atomicity: All operations succeed or none are applied.
  • Consistency: Database remains in a valid state.
  • Isolation: Transactions execute independently.
  • Durability: Committed changes are permanently saved.

Transactions in Java (JDBC)

JDBC supports transactions by disabling auto-commit and using commit/rollback.

Example:

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;

public class TransactionExample {
    public static void main(String[] args) {
        String url = "jdbc:mysql://localhost:3306/bank";
        String user = "root";
        String password = "password";
        try (Connection conn = DriverManager.getConnection(url, user, password)) {
            conn.setAutoCommit(false); // Disable auto-commit
            PreparedStatement stmt1 = conn.prepareStatement(
                "UPDATE Accounts SET balance = balance - ? WHERE account_id = ?");
            PreparedStatement stmt2 = conn.prepareStatement(
                "UPDATE Accounts SET balance = balance + ? WHERE account_id = ?");
            stmt1.setDouble(1, 100.0);
            stmt1.setInt(2, 1);
            stmt2.setDouble(1, 100.0);
            stmt2.setInt(2, 2);
            stmt1.executeUpdate();
            stmt2.executeUpdate();
            conn.commit(); // Commit transaction
            System.out.println("Transfer successful");
        } catch (Exception e) {
            System.out.println("Error: " + e.getMessage());
            try (Connection conn = DriverManager.getConnection(url, user, password)) {
                conn.rollback(); // Rollback on error
            } catch (Exception rollbackEx) {
                System.out.println("Rollback failed: " + rollbackEx.getMessage());
            }
        }
    }
}

Concurrency Control

Concurrency control ensures multiple transactions execute without conflicts.

  • Locking: Use read/write locks to prevent concurrent access.
  • Isolation Levels: Read Uncommitted, Read Committed, Repeatable Read, Serializable.
  • Deadlock Detection: DBMS detects and resolves deadlocks.

Uses of Transactions

  • Data Integrity: Ensure consistent updates (e.g., bank transfers).
  • Concurrent Access: Support multiple users safely.
  • Error Recovery: Rollback failed operations to maintain consistency.
  • Business Logic: Implement complex operations (e.g., order processing).
  • Audit Trails: Track changes for accountability.

Additional Notes

  • Transaction Logs: Record operations for recovery (e.g., redo/undo logs).
  • Two-Phase Commit: Ensures distributed transactions are atomic.
  • Best Practices: Keep transactions short; use appropriate isolation levels.
  • Real-World Example: Transactions manage bank transfers, online orders, and flight bookings.
  • Performance: Avoid long-running transactions to reduce locking overhead.

Indexing

What is Indexing?

Indexing creates data structures (indexes) to improve query performance by enabling faster data retrieval. Indexes are typically implemented as B-trees or hash tables.

  • Primary Index: Built on primary key; ensures unique rows.
  • Secondary Index: Built on non-key columns for faster searches.
  • Clustered Index: Determines physical order of data.
  • Non-Clustered Index: Separate structure with pointers to data.

Creating Indexes in SQL

Indexes are created using the CREATE INDEX statement.

Example:

-- Create primary index
CREATE TABLE Books (
    book_id INT PRIMARY KEY,
    title VARCHAR(100)
);

-- Create secondary index
CREATE INDEX idx_title ON Books(title);

Query Optimization with Indexes

Indexes speed up SELECT queries but slow down INSERT/UPDATE due to index maintenance.

Example (Using Index):

-- Fast retrieval with index
SELECT title FROM Books WHERE title = '1984';

Uses of Indexing

  • Faster Queries: Improve performance for WHERE, JOIN, and ORDER BY clauses.
  • Search Efficiency: Enable quick lookups in large datasets.
  • Scalability: Support high-traffic systems like e-commerce.
  • Data Analysis: Speed up aggregations and reports.
  • Constraint Enforcement: Primary indexes ensure uniqueness.

Additional Notes

  • B-Tree vs. Hash: B-trees for range queries; hash for exact matches.
  • Index Maintenance: Updates to indexed columns require index updates.
  • Best Practices: Index frequently queried columns; avoid over-indexing.
  • Real-World Example: Indexes power search engines, CRM systems, and analytics platforms.
  • Performance Trade-offs: Balance query speed with update overhead.
